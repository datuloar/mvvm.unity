# MVVM Unity

Small typed MVVM package for Unity uGUI and TextMeshPro. Runtime binding is direct C# event subscription: no runtime reflection, scene-name lookup, `Task`, UniTask, or third-party reactive dependency. Common bindings are generated by convention; attributes are needed only for aliases and ambiguity.

```text
Model -> ViewModel -> ObservableValue / ICommand -> generated binding code -> View
```

## Why this package

- Plain-C# ViewModels are testable without a scene.
- Editor-time generation removes repetitive `Bind` overrides.
- Generated code contains direct typed calls and fails at compile time after incompatible refactors.
- Every listener belongs to a `BindingScope` and is removed when the View disables or dies.
- Explicit extension methods cover custom controls without adding reflection to runtime.
- Parameterized commands cover dynamic rows and map nodes without closure/listener cleanup boilerplate.

## Five-minute start

```csharp
using MvvmUnity.Core;

public sealed class CounterViewModel : ViewModel
{
    private readonly ObservableValue<string> _count = new ObservableValue<string>("0");

    public CounterViewModel()
    {
        Increase = new RelayCommand(() => _count.Value = "1");
    }

    public IReadOnlyObservableValue<string> Count => _count;
    public ICommand Increase { get; }
}
```

```csharp
using MvvmUnity.Unity;
using TMPro;
using UnityEngine;
using UnityEngine.UI;

[GenerateBindings]
public sealed partial class CounterView : MvvmView<CounterViewModel>
{
    [SerializeField] private TMP_Text _count;

    [SerializeField] private Button _increase;
}
```

Run `Tools > MVVM > Rebuild Generated Bindings`, then pass the ViewModel from the scene composition root:

```csharp
view.SetViewModel(viewModel);
```

`[GenerateBindings]` infers the ViewModel from `MvvmView<T>`. A serialized `_count` field binds to `Count`, `_increase` binds to `Increase`, and the widget/source types select the binding target. `[Bind(source)]` remains available when names differ or one field needs more than one binding. Use `[IgnoreBinding]` for one matching field owned manually, or `[GenerateBindings(Conventions = false)]` to opt a whole View out of field conventions.

## Snapshot screens

Complex or dynamic screens often render one immutable/snapshot DTO. `StateViewModel<TState>` plus `[Observe]` generates the subscription without one observable per widget:

```csharp
[GenerateBindings]
public sealed partial class InventoryView : MvvmView<InventoryViewModel>
{
    [Observe]
    private void Render(InventoryScreenState state)
    {
        // Paint the dynamic list. No model access here.
    }
}
```

When `[Observe]` has no source, generation selects the only public observable that publishes the method argument type. Ambiguous screens must use explicit `nameof`.

## Installation

The folder is a self-contained Unity package. Copy it to another project's `Packages/com.mvvm.unity` directory or use Package Manager → Add package from disk and select `package.json`. The package has no DI/reactive/async dependency; its Unity adapter targets uGUI and TextMeshPro.

Reference `mvvm.unity.core` from application/domain-facing assemblies, `mvvm.unity` from View assemblies, and keep `mvvm.unity.editor` Editor-only. A DI container is optional.

## Supported workflow

- Unity 2021.3+ API surface; currently verified in Unity 6.3.
- Mono and IL2CPP/AOT-friendly runtime: no generated expression trees or runtime member lookup.
- Generated files are ordinary source and should be committed.
- Package APIs do not depend on VContainer or project-specific types.
